SignWritingの最大の特徴のひとつは、**「コンピュータ上でプレーンテキストとして数学的に一意に表現できる」**点です。これにより、手話を文字列データとしてデータベースに保存し、正規表現で検索し、辞書インデックスを作成することが可能になります。

ここでは、その裏側にある技術仕様について詳しく解説します。

---

## 1. Unicode Sutton SignWriting ブロック

Unicode規格において、Sutton式手話文字は以下の専用ブロックが割り当てられています。

- **割り当て範囲**: `U+1D800` 〜 `U+1DAAF` (補助多言語面: Supplementary Multilingual Plane)
- **正式名**: `Sutton SignWriting` (スクリプトコード: `Sgnw`)
- **導入バージョン**: Unicode 8.0 (2015年)
- **収録文字数**: 688コードポイント（現在672文字が定義済み）

このブロックには、基本となる手のルートシェイプ（S100〜S387等）、動きの矢印のベース、顔の表情パーツ、接触記号、数字（座標表現用）、書字方向指示子、句読点などが定義されています。

---

## 2. 2次元表現と2つのテキスト規格：FSW と SWU

手話文字は二次元（空間的）に記号を配置するため、プレーンテキスト（一次元）で表すには特別なフォーマットが必要です。これには、同型（Isomorphic：一対一変換可能）な2つの規格が存在します。

```
[ 手話記号の画像 (2D) ]
       ▲
       │  (レンダリングエンジン)
       │
[ 空間レイアウトを表す一次元テキスト ]
 ├─① FSW (ASCII文字ベース / 2012年) ➡ 「M518x529S14c20517x510...」
 └─② SWU (Unicodeコードポイントベース / 実験的) ➡ UnicodeのSgnw文字の並び
```

### ① FSW (Formal SignWriting in ASCII)
ASCII文字（英数字）のみを用いて手話文字を表現する、最も広くサポートされている安定した文字フォーマットです。
- **特徴**: すべてのブラウザ、データベース、URL、テキストファイルで何のエスケープ処理もなしに安全に送受信・保存・処理ができます。

### ② SWU (SignWriting in Unicode)
UnicodeのSutton SignWritingブロックの文字を直接並べて表現するフォーマットです。
- **特徴**: FSWと完全に1対1で相互変換可能ですが、特殊なフォントのサポートが必要な場合があり、主にUnicodeの思想に厳密に沿ってデータを表現したい場合に使用されます。

## 3. FSW（Formal SignWriting）の構造と文法

最も一般的に使われている **FSW 文字列** の文法構造を解剖してみましょう。

FSW文字列は、大きく分けて**「Aシーケンス（時系列部）」**と**「Mサインボックス（空間レイアウト部）」**の2つの部分から構成されます。

```
例: AS10011S10019S2e704M525x535S10011501x466S2e704510x500S10019476x475
   └─── Aシーケンス (ソート用順序) ───┘└─── Mサインボックス (実際の2Dレイアウト) ───┘
```

通常、Webページ上で手話文字を描画（レンダリング）するだけであれば、2Dレイアウト部分である **「Mサインボックス（Mから始まる文字列）」のみで十分に描画可能** です。

### Mサインボックス（2Dレイアウト部分）の分解

以下の実際の手話文字のFSWコードを例に、その文法を解読します。

```
M518x529S14c20517x510S27106493x483S20500489x511
```

これをトークン（意味のあるパーツ）ごとに分解すると、以下のようになります。

| トークン | タイプ | 意味・解説 |
| :--- | :--- | :--- |
| **`M`** | 開始子 | **M**aximum (またはSignbox) の開始を表すマーカー。 |
| **`518x529`** | サインボックスサイズ | この手話文字のキャンバスサイズが「幅 518、高さ 529」であることを示します（基準座標は `500x500` で、そこから周囲に広がります）。 |
| **`S14c20`** | シンボルキー 1 | `S14c20` というIDを持つ手話文字記号（特定の平手記号）。 |
| **`517x510`** | 座標 1 | シンボル 1 をキャンバスの座標 `(X: 517, Y: 510)` に配置することを示します。 |
| **`S27106`** | シンボルキー 2 | `S27106` というIDを持つ記号（特定の動きの矢印）。 |
| **`493x483`** | 座標 2 | シンボル 2 をキャンバスの座標 `(X: 493, Y: 483)` に配置することを示します。 |
| **`S20500`** | シンボルキー 3 | `S20500` （タッチを表すアスタリスク `*` のID）。 |
| **`489x511`** | 座標 3 | シンボル 3 をキャンバスの座標 `(X: 489, Y: 511)` に配置することを示します。 |

### シンボルキー (Symbol Key) の詳細構造
シンボルキー（例：`S14c20`）は、以下のような構造になっています。

- `S` (プレフィックス) ＋ `14c` (ベースシェイプ: 16進数3桁) ＋ `2` (塗りつぶし状態: 16進数1桁) ＋ `0` (回転角: 16進数1桁)
  - `S14c` ＝ 「親指を横に広げた平手」のベース
  - `2` ＝ 「手の側面（半分黒・半分白）」の塗りつぶし
  - `0` ＝ 「指先が真上を向いている」回転（0度）

## 4. なぜこれが画期的なのか？ (開発者のメリット)

### 1. 正規表現（Regex）による手話の検索
FSWはプレーンテキストなので、特定の記号を含む手話を検索したい場合、データベースのSQLやコード内で通常の「文字列マッチング」を行うだけで実現できます。
- 例：`S20500`（タッチ）を含む手話をデータベースから全て取得したい場合、`%S20500%` という部分一致クエリや、正規表現 `/S20500/` で簡単にフィルタリングできます。手話言語学の検索システムを構築する上で、これは革命的なアプローチです。

### 2. レンダリングの軽量性
画像ファイル（PNGやGIF）を使用する場合、何万種類もある手話記号ごとに画像ファイルを用意し、サーバーからロードする必要があります。しかしFSWであれば、わずか数十バイトの文字列をHTMLに埋め込むだけで、ブラウザがCDN経由の共通フォントを使ってSVGとして綺麗に即座にレンダリングします。ページの読み込み速度やサーバー容量は劇的に削減されます。

## まとめ

Sutton式手話文字は、単なるビジュアルイラストではなく、**「Unicode規格」**と**「Formal SignWriting (FSW) 文法」**によって厳密に定義された**デジタル文字**です。

この仕様により、手話は歴史上はじめて、話し言葉（日本語や英語）と全く同等に「検索・ソート・システム処理」が可能な、コンピュータ時代の真の「書記体系」となりました。
